# Internationalisation

The site ships **Spanish only**. The machinery for more languages is in place
and inert — nothing extra is rendered, no bundle cost — so adding one later is a
contained, mechanical change rather than a refactor.

## How it works

| File                        | Role                                                      |
| --------------------------- | --------------------------------------------------------- |
| `src/i18n/config.ts`        | Which locales exist, their labels and BCP-47 tags         |
| `src/i18n/locales/es.ts`    | The reference locale — its keys define the contract       |
| `src/i18n/locales/index.ts` | Registry mapping locale code → translation table          |
| `src/i18n/utils.ts`         | `useTranslations()`, `localePath()`, `alternateLocales()` |

Astro's built-in i18n handles routing from `LOCALES` alone. Spanish is the
default and is served from the root (`qa-ulew.tv/`), not `/es/`.

## Using translations in a component

```astro
---
import { DEFAULT_LOCALE, isLocale } from "~/i18n/config";
import { useTranslations } from "~/i18n/utils";

const t = useTranslations(isLocale(Astro.currentLocale) ? Astro.currentLocale : DEFAULT_LOCALE);
---

<h1>{t("hero.title")}</h1>
<p>{t("footer.copyright", { year: 2026 })}</p>
```

`t()` only accepts keys that exist in `es.ts` — `TranslationKey` is a closed
union derived from it, so a typo is a compile error, not a blank on the page.

Interpolation uses `{braces}`:

```ts
export const es = {
  "social.followOn": "Seguinos en {platform}",
} as const;
```

## Adding a language

Three steps. The build will not let you finish them halfway.

**1. Register the locale** in `src/i18n/config.ts`:

```ts
export const LOCALES = ["es", "en"] as const;

export const LOCALE_META: Record<Locale, LocaleMeta> = {
  es: { label: "Español", htmlLang: "es-GT", ogLocale: "es_GT", dir: "ltr" },
  en: { label: "English", htmlLang: "en", ogLocale: "en_US", dir: "ltr" },
};
```

**2. Translate.** Copy `locales/es.ts` to `locales/en.ts` and type it against
the contract:

```ts
import type { TranslationKey } from "./index";

export const en: Record<TranslationKey, string> = {
  "site.title": "Qa Ulew",
  // ... every key. A missing one fails `pnpm check`.
};
```

**3. Register the table** in `locales/index.ts`:

```ts
import { en } from "./en";

export const translations: Record<Locale, Translations> = { es, en };
```

That is the whole change. You get for free:

- `/en/` routes for every existing page — no new files
- a language picker in the header (it renders itself once `LOCALES.length > 1`)
- `hreflang` alternate tags in `<head>`
- per-locale sitemap entries
- correct `lang` and `dir` attributes on `<html>`

Run `pnpm check` to confirm nothing is missing, then `pnpm build`.

## Notes

- **Never hardcode a user-visible string in a component.** It cannot be
  translated later and it will be missed. Add a key to `es.ts` instead.
- **Video titles are content, not UI copy.** They live in `config/site.ts`.
  When a second locale arrives, move `FEATURED_VIDEOS` to an Astro content
  collection with one entry per locale — see [content.md](./content.md).
- Guatemalan Spanish uses _voseo_ (`mirá`, `seguinos`, `escribinos`). The
  existing copy follows it; keep new copy consistent.
- The language picker preserves the current path, so switching language on a
  sub-page keeps you on that page.
